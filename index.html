CENTRE DE CONNEXIONS

Mes comptes

Retrouve les services importants depuis un seul endroit.

Important : « Ouvrir » permet d’aller sur le site officiel. Pour afficher des données réelles directement dans ClemOS, il faut autoriser le service et parfois créer une application développeur. Ce n’est pas un mot de passe à inventer : suis les guides ci-dessous, étape par étape. Ne saisis jamais ton mot de passe Google, Yahoo, Twitch, Discord ou autre dans un formulaire ClemOS.

Guides de connexion, étape par étape

Choisis un service. Les liens ouvrent les pages officielles dans un nouvel onglet.
À savoir : une API est une porte d’accès technique aux données d’un service. OAuth est l’écran officiel où tu te connectes chez le fournisseur et autorises ClemOS. L’ID client est généralement un identifiant public, pas ton mot de passe. Un secret client ou un jeton privé ne doit jamais être collé dans ce fichier HTML.
Google / Gmail — lire les vrais e-mails dans ClemOS
  1. Ouvre Google Cloud Console et connecte-toi au compte Google que tu veux utiliser.
  2. Crée un projet (le nom peut être « ClemOS ») ou sélectionne un projet existant.
  3. Dans « API et services » → « Bibliothèque », cherche Gmail API, ouvre-la puis clique sur « Activer ».
  4. Dans « Écran de consentement OAuth » ou « Google Auth Platform », renseigne les informations demandées. Si l’application est en mode test, ajoute ton adresse Google dans les utilisateurs test.
  5. Dans « Clients » / « Identifiants », crée un client OAuth de type Application Web. Dans « Origines JavaScript autorisées », ajoute l’origine exacte du site, par exemple https://TON-PSEUDO.github.io (sans chemin après le domaine). Si ton site est un projet GitHub Pages, l’URL de page peut contenir un chemin, mais l’origine reste le domaine.
  6. Copie l’ID client qui se termine par .apps.googleusercontent.com, puis colle-le dans « Mails » → « Connexion Gmail » dans ClemOS.
  7. Clique sur « Connecter Gmail », choisis le bon compte et accepte les permissions. Reviens à ClemOS : les messages doivent se charger si l’API et l’autorisation sont correctement configurées.

Si ça bloque : vérifie l’origine autorisée, que Gmail API est activée, que ton compte est ajouté aux utilisateurs test si nécessaire et que tu utilises l’ID client du bon projet. Ne partage jamais un jeton d’accès.

Outlook / Hotmail — lire les e-mails avec Microsoft Graph
  1. Ouvre Microsoft Entra, puis « Identité » → « Applications » → « Inscriptions d’applications ».
  2. Crée une inscription. Choisis les types de comptes qui correspondent à ton compte (personnel Microsoft et/ou comptes d’organisation), puis ajoute l’URL de ClemOS comme URI de redirection de type Application monopage (SPA).
  3. Copie l’ID d’application (client), pas un secret client, et colle-le dans « Mails » → « Outlook / Microsoft 365 ».
  4. Dans les autorisations API Microsoft Graph, vérifie les permissions déléguées User.Read et Mail.Read. Demande le consentement nécessaire si Microsoft le demande.
  5. Dans ClemOS, clique « Connecter Outlook », connecte-toi dans la fenêtre Microsoft et accepte les autorisations.

Si la fenêtre échoue, vérifie surtout l’URI de redirection : elle doit correspondre exactement à l’adresse utilisée pour ouvrir ClemOS. Aucun secret client ne doit être placé dans GitHub Pages.

Microsoft Entra ↗Microsoft Graph ↗
Yahoo Mail — nécessite un petit serveur sécurisé
  1. Ouvre Yahoo Developer Network et vérifie les possibilités d’accès Mail actuellement proposées pour ton compte et ton application.
  2. Si l’accès Mail/OAuth est disponible, crée une application et récupère les identifiants demandés. Les possibilités et conditions de Yahoo peuvent varier selon l’accès développeur accordé.
  3. Crée ensuite un backend HTTPS (par exemple un service Node.js) qui gère le retour OAuth, conserve les secrets côté serveur et appelle l’API autorisée. GitHub Pages ne peut pas exécuter ce serveur.
  4. Le backend doit fournir une route de santé et des routes d’authentification/lecture conçues pour ClemOS. Déploie-le, configure les URL de retour OAuth et les variables secrètes dans les paramètres privés du service d’hébergement.
  5. Quand le backend est réellement prêt, colle son URL HTTPS dans « Mails » → « Yahoo Mail » puis clique « Connecter Yahoo ».

Important : enregistrer une URL ne connecte pas Yahoo. Le backend n’existe pas encore dans cette version ; la lecture Yahoo ne fonctionnera pas tant qu’il n’aura pas été développé, déployé et testé. Ne mets pas de mot de passe Yahoo ni de secret OAuth dans ClemOS.

Yahoo Developer Network ↗Yahoo Mail ↗
YouTube — chaîne et statistiques
  1. Ouvre Google Cloud Console et crée ou sélectionne le projet de ClemOS.
  2. Dans « API et services » → « Bibliothèque », active YouTube Data API v3.
  3. Si ClemOS doit accéder à des données privées de ta chaîne, configure l’écran de consentement OAuth et crée un client OAuth adapté au site.
  4. Une vraie intégration doit ensuite être programmée dans ClemOS pour demander uniquement les autorisations nécessaires et appeler YouTube Data API. L’ID client Gmail seul ne crée pas automatiquement cette fonction.

La carte YouTube actuelle ouvre YouTube Studio : elle ne lit pas encore les statistiques directement dans ClemOS. Certaines données sont publiques, mais les données privées de ta chaîne nécessitent une autorisation.

Twitch — chaîne, live et statistiques
  1. Ouvre Twitch Developer Console et connecte-toi à Twitch.
  2. Enregistre une application. Indique un nom, la catégorie appropriée et une URL de redirection autorisée qui correspondra exactement à la configuration OAuth.
  3. Récupère le Client ID. Le client secret, s’il est fourni, reste côté serveur : ne le colle jamais dans ClemOS ni dans un dépôt GitHub public.
  4. Pour afficher des données autorisées, ClemOS doit implémenter OAuth Twitch et appeler l’API Helix avec les scopes adaptés à la fonction souhaitée.

La carte Twitch actuelle ouvre le tableau de bord. Elle ne connecte pas encore l’API ni ne récupère les statistiques dans ClemOS.

Discord — serveur et bot
  1. Pour une connexion utilisateur, ouvre le portail développeur Discord et crée une application.
  2. Dans OAuth2, configure une URL de redirection et les scopes strictement nécessaires. Pour une connexion utilisateur, Discord utilise OAuth2.
  3. Pour lire ou gérer des événements de serveur, les permissions dépendent de la fonction. Un bot doit être ajouté au serveur par une personne autorisée.
  4. Les jetons de bot et secrets doivent rester dans un backend privé. Ne les place jamais dans le HTML publié.

La carte Discord actuelle est un raccourci ; la connexion et les fonctions serveur ne sont pas encore implémentées.

GitHub — dépôts et projets
  1. Pour simplement consulter tes dépôts, connecte-toi sur GitHub : aucun branchement API n’est nécessaire pour ouvrir le site.
  2. Pour lire des dépôts publics dans ClemOS, une intégration peut utiliser l’API REST GitHub avec ses limites d’utilisation.
  3. Pour accéder à tes dépôts privés ou effectuer des actions, crée une GitHub App ou utilise un flux OAuth adapté, avec des permissions minimales.
  4. Ne colle jamais un Personal Access Token dans le HTML public. Les actions sensibles doivent passer par une architecture sécurisée et des autorisations explicites.

La carte GitHub actuelle ouvre le site ; la lecture ou la modification de dépôts depuis ClemOS n’est pas encore branchée.

École Directe — emploi du temps
  1. Connecte-toi uniquement sur le site ou l’application officielle d’École Directe.
  2. Regarde si ton établissement propose une exportation ou un abonnement de calendrier au format .ics. Si oui, télécharge ou exporte le fichier depuis l’interface officielle.
  3. Dans ClemOS → Agenda, utilise « Importer un agenda (.ics) » pour ajouter les événements.

Yahoo, Google, Microsoft : c’est quoi une API et OAuth ?
  • OAuth : tu autorises un service depuis sa propre page officielle, sans transmettre ton mot de passe à ClemOS.
  • API : un moyen officiel pour un programme de lire ou modifier certaines données après autorisation.
  • ID client : identifiant d’application, à distinguer du secret client et des jetons.
  • Backend : un serveur séparé nécessaire pour garder des secrets et exécuter certaines opérations. GitHub Pages ne peut héberger que les fichiers statiques de ClemOS.
  • Coût : certains outils et hébergeurs proposent une offre gratuite, mais les quotas, validations et conditions peuvent changer. Une API n’est pas automatiquement disponible ou gratuite.

Connexion Gmail

Lecture des messages via l'API officielle Gmail.
Gmail n'est pas connecté.
Guide complet : connecter une ou plusieurs adresses Gmail
  1. Ouvre Google Cloud Console et connecte-toi au compte Google qui gère ton application. En haut, crée un projet nommé par exemple ClemOS Mail, ou sélectionne ton projet existant.
  2. Ouvre Gmail API, vérifie le nom du projet en haut, puis clique sur Activer.
  3. Ouvre Google Auth Platform → Branding et renseigne le nom de l’application et l’adresse de contact demandée. Enregistre.
  4. Va sur Google Auth Platform → Audience. Si l’application est en mode Test, ajoute dans « Utilisateurs testeurs » chaque adresse Google qui devra essayer ClemOS, puis enregistre. C’est ce qui corrige normalement l’erreur 403 access_denied « seuls les testeurs approuvés ».
  5. Ouvre Google Auth Platform → Clients et crée un client OAuth de type Application Web. Dans « Origines JavaScript autorisées », ajoute exactement https://clemsupp.github.io (sans /ClemOS/). Pour ce flux Google en fenêtre popup, ne crée pas d’URI de redirection au hasard : ajoute-en une uniquement si un autre flux de connexion la demande explicitement.
  6. Copie l’ID client qui finit par .apps.googleusercontent.com. Ce n’est pas le secret client. Colle cet ID dans le champ ci-dessus et clique sur « Connecter Gmail ».
  7. Google ouvre une fenêtre officielle : choisis l’adresse Gmail souhaitée et accepte l’accès en lecture aux messages. Pour ajouter une deuxième adresse, reviens dans ClemOS, sélectionne « Google / Gmail » dans « Ajouter un compte », puis recommence et choisis l’autre adresse.
  8. Les messages apparaissent dans « Tous les comptes ». Chaque message affiche le fournisseur et l’adresse d’origine. Clique sur une adresse dans « Mes adresses connectées » pour filtrer la liste sur ce compte.

Si ça bloque : 401 invalid_client indique souvent un ID client incorrect, un mauvais type de client ou une origine absente/mal saisie. 403 access_denied en mode test signifie généralement que l’adresse utilisée doit être ajoutée aux utilisateurs testeurs. Après avoir modifié Google Cloud, attends quelques minutes et réessaie.

Vie privée : ClemOS ne te demande jamais ton mot de passe Gmail. Les jetons de session ne sont gardés qu’en mémoire dans cette version ; si tu actualises la page, il faudra reconnecter les comptes. L’application actuelle lit les messages, elle ne les envoie pas et ne les supprime pas.

ClemOS, ton espace personnel.

ClemOS est une interface autonome conçue pour GitHub Pages. Les données locales ne se synchronisent pas automatiquement entre appareils. Une sauvegarde exportée peut être conservée ailleurs pour éviter de perdre tes notes et tâches.
